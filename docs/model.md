# SAW–TSO operational scope

**Processes.** There are p sequential processes, each running a finite sequence of `find(x)` / `unite(x,y)` requests on a fixed universe U={0,...,n−1}. The adversarial scheduler can stall a process after any atomic or local step for any finite or unbounded duration. No fair-scheduling assumption is made for the safety property. Progress claims require infinitely many steps by active processes.

**Shared memory.** Array `A[0..n−1]` of 64-bit atomics. `A[i] = (version << 32) | parent`. One-word read/CAS; no multiword CAS, locks in P1, helping descriptors, unbounded allocation or atomic rank updates. Parent links in P1 only go from higher ID toward lower ID. Versions advance by one on successful link or split CAS, with no wrap in the claimed finite scope.

**Memory model.** C++20 acquire loads, acq_rel successful CAS, acquire failed-CAS readback, and relaxed-only metrics. For x86 TSO, ordinary stores are per-thread FIFO buffered and a load may bypass *other-location* buffered stores. Locked CAS drains the local buffer and performs an atomic RMW. The operational DSU checker currently contains **only CAS writes**, so no pending normal store can appear. The standalone store-buffering litmus validates that the operational TSO rules permit the classic `(r0,r1)=(0,0)` outcome while SC forbids it; this does not establish a TSO-only DSU failure.

**Progress target.** Lock-freedom (infinite aggregate active steps imply infinite completed operations). Wait-freedom is not claimed. A process stalled forever need not complete. Global progress needs a separate rigorous argument; native throughput measurements cannot prove lock-freedom.

**Safety semantics.** Sequential DSU partition starts as n singleton sets; `unite` returns `true` iff the two elements were in distinct sets immediately before its linearization; `find` returns the current canonical minimum-ID representative under P1's linking policy. Linearizability respects real-time precedence `end(A) < start(B) => A before B` and needs an assignment of a sequential order to all completed operations. The offline checker explores orders only for fully completed bounded histories; operation logging occurs at invocation/response boundaries.

**Events.** The executable step machine includes root loads, comparisons, root validation reads, atomic root CAS, CAS failure retry, and completion. Every step is an admissible scheduler yield. Arbitrary stalls are represented by choosing another process's step. Unsafe blind-write is a separately defined negative-control variant, not the B3 parent-CAS implementation.

**Limitations of correspondence.** The operational checker abstracts instruction steps, compiler reorderings, detailed language-level C++ data-race questions, and per-object visibility beyond its atomic-CAS submodel. Nidhugg/GenMC optional runs check a small C11 translation, not a fully machine-checked equivalence theorem for C++ sources. The model is explicitly not a full axiomatization of ARMv8/RC11.
